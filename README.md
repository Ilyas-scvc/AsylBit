# BEAT//FORM

Интерактивный аудиореактивный сайт для музыкального продюсера: пользователь бросает на страницу свой трек, и 3D‑форма отвечает на реальный сигнал — бас, середину, верха, вероятные удары kick / snare / hat. Вся обработка идёт **локально в браузере**: файл никуда не загружается, микрофон не используется.

Стек: React 19 · TypeScript · Vite 8 · three.js + React Three Fiber · Web Audio API · GLSL · Zustand · Vitest.

---

## Запуск

Нужен Node.js 24 (версия для сборки указана в `.node-version`).

```bash
npm install
npm run dev
```

Открыть адрес, который покажет Vite (по умолчанию http://localhost:5173), бросить аудиофайл на страницу или нажать **TEST PATTERN** — встроенный синтезированный бит с известными позициями ударов.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер с HMR |
| `npm run build` | проверка типов (`tsc -b`) + production-сборка в `dist/` |
| `npm run preview` | локальный просмотр production-сборки |
| `npm test` | автотесты (Vitest) |
| `npm run typecheck` | только проверка типов |

`dist/` — статические файлы, их можно отдавать любым статическим хостингом.

## Что умеет

- **Загрузка**: drag-and-drop в любое место страницы или выбор файла. MP3, WAV, FLAC, OGG/Opus, M4A/AAC (если браузер их декодирует). Понятные ошибки: не аудио, пустой файл, > 512 МБ, неподдерживаемый формат / битые данные.
- **Плеер**: Play/Pause, перемотка по waveform-таймлайну (мышь, тач, клавиатура), Repeat, громкость и mute, текущее время / длительность, замена файла, полноэкранный режим.
- **Три режима визуализации** (общий движок анализа, разные правила отображения):
  - **MODE 01 — PULSE OBJECT** — икосфера с шумовой деформацией в вершинном шейдере и «топографическими» изолиниями. Бас → масштаб и крупные лопасти; kick → короткий импульс на пружине + вспышка контура; mid → складки поверхности и скорость течения; high → мелкая рябь и оболочка частиц; snare → кольцевая волна по поверхности.
  - **MODE 02 — RADIAL SPECTRUM** — 192 клиновидные линии по логарифмической шкале 30 Гц–16 кГц (зеркально), у каждой полосы своя инерция (низы крупно и медленно, верха мелко и быстро), peak-hold, туннель из прошлых спектров, осциллограф внутри, частицы из полос, где звучат hats, ударная волна от snare.
  - **MODE 03 — WAVE FIELD** — поле линий в 3D: каждая строка — снимок музыки, уезжающий вглубь. Бас — широкие волны, mid — изгибает геометрию, high — мелкая быстрая рябь. Камера медленно дрейфует.
- **Состояние ожидания**: до загрузки и в тишине сцена медленно «дышит», без имитации ударов.
- **Настройки** (сохраняются в `localStorage`, значения ограничены безопасными диапазонами): режим, основной цвет, фон, чувствительность BASS/MID/HIGH, BEAT IMPACT, SMOOTHING, INTENSITY, PARTICLES, ROTATION, REDUCED MOTION (AUTO по системной настройке / ON / OFF), FFT 2048/4096, DETAIL (AUTO/HIGH/LOW), сброс к умолчаниям. Все параметры применяются на лету.
- **Экспорт видео (этап 2)**: WebM (VP9/VP8 + Opus) 16:9 1920×1080, 9:16 1080×1920, 1:1 1080×1080, 30/60 FPS, с исходным звуком файла. Подробности и ограничения — ниже.
- **Клавиши** (когда фокус не в поле ввода): `Space` play/pause, `← →` ±5 с, `1 2 3` режим, `F` fullscreen, `L` repeat, `M` mute, `S` настройки.

## Архитектура

```
src/
  audio/
    engine/            1. Воспроизведение
      AudioEngine.ts       HTMLAudioElement → MediaElementSource → Analyser → Gain → destination
      PlaybackClock.ts     сглаженные часы медиа (истина — currentTime элемента)
      fileValidation.ts    проверка файла до загрузки
    analysis/          2. Анализ
      RealtimeAnalyzer.ts  RMS, полосы, лог-спектр, spectral flux, онсеты — каждый кадр
      PreAnalyzer.ts       декодирование 22.05 кГц + Worker, отмена, LRU-кэш
      EventScheduler.ts    проигрывание карты событий по реальной позиции
      AnalysisHub.ts       склейка: задержка под латентность, импульсы, AudioFrame
      frame.ts             единый изменяемый AudioFrame, который читают рендереры
    dsp/               3. Детекция (чистые функции, покрыты тестами)
      fft.ts bands.ts envelope.ts onset.ts offlineAnalysis.ts testPattern.ts wav.ts
    worker/            pre-analysis в Web Worker
    controller.ts      связывает движок, анализ и UI-сторы
  visual/              4. Рендер
    WebGLStage.tsx       R3F Canvas (грузится лениво), потеря контекста, DPR
    Scene.tsx            тик анализа до рендера, авто-качество
    modes/               PulseObject, RadialSpectrum, WaveField
    fallback/            Canvas 2D-версия всех трёх режимов
  ui/                  5. Интерфейс: Header, Hero, HUD, PlayerBar, Timeline, SettingsPanel, ExportPanel
  state/               6. Настройки и состояние: settings (persist + clamp), player, export, notice
  export/              экспорт WebM
tests/                 Vitest
```

**Поток данных за кадр.** Один `requestAnimationFrame`-цикл (R3F `useFrame` с приоритетом −10, либо цикл 2D-фолбэка) вызывает `analysisHub.tick()`. Хаб читает анализатор один раз, складывает результат в линию задержки, выдаёт в `AudioFrame` срез, соответствующий тому, что сейчас реально слышно, запускает события и затухание импульсов. Режимы читают `AudioFrame` и обновляют uniforms / буферы — без React state, без аллокаций в цикле. HUD и таймлайн пишут прямо в DOM.

### Аудиодвижок

- `MediaElementAudioSourceNode` создаётся **один раз** на весь сеанс; новый файл меняет только `src` элемента, поэтому двойное воспроизведение невозможно. Object URL старого файла освобождается.
- `AudioContext` создаётся/возобновляется синхронно внутри пользовательского жеста (autoplay policy).
- Анализатор стоит **до** громкости, поэтому визуал не зависит от положения ползунка громкости.
- Время — реальная позиция `currentTime`, а не счётчик кадров. Экстраполяция между обновлениями включается только когда медиа реально пошло (иначе стартовая задержка `play()` опережала бы звук).
- **Компенсация латентности вывода**: анализатор и `currentTime` опережают динамики на `outputLatency + baseLatency` (10–60 мс проводной выход, 150–250 мс Bluetooth). Визуал задерживается на эту величину минус ~20 мс задержки дисплея; HUD показывает `AV SYNC +N MS`.

### Анализ

- Полосы считаются от реальной частоты дискретизации и размера FFT: BASS 20–150 Гц, MID 150–2000 Гц, HIGH 2–12 кГц; для детекции отдельно 35–140 (kick), 250–2500 (body), 2.5–6.5 кГц (snap), 7–14 кГц (air).
- Уровни: адаптивная нормализация (быстрый подъём / медленный спад опорного пика с нижней границей, чтобы тишину не «вытягивало»), attack/release, чувствительность.
- **Spectral flux** в лог-сжатом спектре с max-фильтром по частоте (±1 бин) и **по времени** (последние ~60 мс): провал и возврат уровня (биения хвоста kick с удерживаемым басом) не считается новой атакой.
- **Онсеты** — адаптивный порог по медиане окна + минимальный подъём уровня в полосе + абсолютный гейт + рефрактерный период + гистерезис. Kick дополнительно требует охвата большей части полосы и силы, сравнимой с недавними kick. Поэтому **наличие баса ≠ удар**: удерживаемая нота не порождает повторных kick.
- **Классификация kick / snare / hat — эвристика** по форме транзиента на готовом миксе, а не разделение инструментов. Возможны ошибки, особенно на плотных миксах и с пересекающимися партиями.

### Предварительный анализ

После загрузки: декодирование в `OfflineAudioContext` с частотой 22.05 кГц (ограничение памяти) → моно → **Web Worker**: FFT 1024 / hop 256 (11.6 мс), облегчённая waveform (peak + RMS), карта энергии bass/mid/high по времени, карта событий (non-causal peak picking), оценка BPM (автокорреляция; только для информации — удары никогда не подменяются метрономом). Работа отменяется при замене файла (worker завершается), результат кэшируется в памяти (3 последних файла). Пока карта не готова — работает real-time детектор; при перемотке события пропущенного участка не срабатывают. Треки длиннее 15 минут анализируются только в реальном времени.

### Производительность

DPR ограничен (2 / 1.5), авто-качество понижает DPR, затем детализацию, если частота кадров держится ниже ~42 FPS; рендер останавливается, когда сцена прокручена из вида или вкладка скрыта; геометрия — один-два draw call на режим; three.js-часть грузится отдельным чанком после первой отрисовки страницы. Потеря WebGL-контекста обрабатывается: при восстановлении сцена продолжает работу, если восстановления нет 3 с — включается Canvas 2D.

## Экспорт видео

Настройки → **[07] EXPORT VIDEO** → кадр и FPS → **RECORD**. Трек проигрывается один раз с начала, canvas рендерится ровно в выбранном разрешении, звук берётся из Web Audio графа (сам файл, не микрофон), всё записывается `MediaRecorder` в WebM. После записи — **SAVE .WEBM**. Длительность дописывается в заголовок файла (`fix-webm-duration`), чтобы файл перематывался в плеерах.

Ограничения:
- запись идёт в реальном времени (3-минутный трек — 3 минуты); вкладка должна оставаться видимой, иначе браузер замедляет кадры;
- только **WebM**: MP4 не предлагается, пока нет проверенного способа кодирования;
- если браузер не умеет `MediaRecorder` + WebM + `canvas.captureStream`, кнопки нет — вместо неё показывается причина;
- на слабой графике 1080p60 может пропускать кадры (звук при этом остаётся непрерывным).

## Тестирование

### Автотесты (`npm test`, 63 теста, 7 файлов)

- **offlineAnalysis** — на синтезированном паттерне с известными позициями: kick recall/precision ≥ 0.95/0.9 (фактически 100%), snare ≥ 0.9/0.85, hats ≥ 0.85/0.85, средняя ошибка времени < 20 мс, BPM 120 ± 2; нет событий в цифровой тишине, в шумовом полу −80 dBFS и на удерживаемом басе; ограниченные размеры waveform / карты полос.
- **realtimeAnalyzer** — эмуляция AnalyserNode (окно Блэкмана, |X|/N в дБ), 60 FPS, FFT 2048 и 4096 при 48 кГц: kick ≥ 0.85/0.85 (фактически 32/32 без ложных), snare, hats; возврат к нулю в тишине; held-bass не даёт kick; чувствительность масштабирует уровни; сброс при перемотке подавляет ложные срабатывания.
- **analysisHub** — события по слышимому времени с учётом латентности, нет событий на паузе, нет событий пропущенного при перемотке участка, real-time режим без карты, покой в тишине.
- **eventScheduler**, **settings** (санитизация, clamp, тёмный фон), **fileValidation**, **dsp** (FFT, полосы, огибающие, пружина, peak picking, трекер, часы, WAV).

### Проверено вручную в браузере (Chromium, Intel UHD, dev и production-сборка)

загрузка WAV через UI; play / pause / seek вперёд и назад / repeat с переходом через конец; замена трека во время анализа (дважды подряд); `.txt` и битый `.mp3`; один и тот же `AudioContext` после замен; синхронизация событий (0–19 мс после слышимого момента); тишина и удерживаемый бас; изменение чувствительности на лету; все три режима; мобильная раскладка 375×812 и bottom-sheet настроек; Canvas 2D-фолбэк (`?renderer=2d`); потеря / восстановление WebGL-контекста и переход на 2D; экспорт 1:1 и 9:16 (размер, длительность, наличие исходного звука и кадров проверены декодированием файла).

Не проверялось: Safari / iOS и Firefox (код использует только стандартные API, но на этих браузерах не запускался), реальные мобильные устройства и долгие (> 10 мин) треки.

## Отладка

- `?renderer=2d` — принудительно включить Canvas 2D-фолбэк.
- В dev-сборке доступен `window.__beatform` (движок, хаб анализа, сторы, экспорт) для ручной проверки из консоли; в production его нет.
- Проект лежит в папке OneDrive: если HMR пропустил изменение файла (страница не обновилась или в консоли ошибка от старой версии модуля) — пересохраните файл или перезапустите `npm run dev`.

## Приватность

Аудио не покидает вкладку: нет загрузок на сервер, нет аналитики, нет микрофона. В `localStorage` хранятся только настройки и громкость.

## Референсы

Визуальное направление вдохновлено сайтами chayknbayk.com (сетка из тонких линий, технические подписи в скобках, каркасная сфера) и saesh000.net (крупная типографика у нижнего края). Код, тексты и графика — оригинальные.

## Публикация в Cloudflare Pages

Подключите GitHub-репозиторий через **Workers & Pages → Create application → Pages → Connect to Git**.

| Настройка | Значение |
| --- | --- |
| Production branch | `main` |
| Framework preset | React (Vite), либо None с настройками ниже |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | оставить пустым (корень репозитория) |
| Node.js | `24.19.0`, читается из `.node-version` |

Cloudflare устанавливает зависимости по `package.json` и `package-lock.json`. Переменные окружения приложения и серверная часть не нужны. Папки `node_modules/`, `dist/`, `.claude/` и файлы `.env*` (кроме безопасного `.env.example`) не отправляются в GitHub. После подключения каждый push в `main` запускает новую публикацию.

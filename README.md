# BEAT//FORM 2.0

Аудиореактивный визуализатор и студия рендера видео для музыкального продюсера. Пользователь бросает на страницу свой трек, выбирает одну из девяти сцен, настраивает её (параметры, аудиомодуляция, эффекты, пресеты) и экспортирует видео MP4 / MOV / WebM с исходным звуком — кадр за кадром, без записи экрана. Вся обработка идёт **локально в браузере**: файл никуда не загружается, сервер не нужен, микрофон не используется.

Стек: React 19 · TypeScript · Vite 8 · three.js (императивный движок, GLSL) · Web Audio API · WebCodecs + [Mediabunny](https://mediabunny.dev) · Zustand · Vitest.

---

## Запуск

Нужен Node.js 24 (версия для сборки указана в `.node-version`).

```bash
npm install
npm run dev
```

Открыть адрес, который покажет Vite (по умолчанию http://localhost:5173), бросить аудиофайл на страницу или нажать **TEST PATTERN** — встроенный синтезированный бит 120 BPM с известными позициями ударов.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер с HMR |
| `npm run build` | проверка типов (`tsc -b`) + production-сборка в `dist/` |
| `npm run preview` | локальный просмотр production-сборки |
| `npm test` | автотесты (Vitest) |
| `npm run typecheck` | только проверка типов |

`dist/` — статические файлы, их можно отдавать любым статическим хостингом.

## Что умеет

- **Загрузка и плеер** (как в 1.0): drag-and-drop или выбор файла (MP3, WAV, FLAC, OGG/Opus, M4A/AAC — если браузер их декодирует), понятные ошибки, Play/Pause, перемотка по waveform, Repeat, громкость, fullscreen.
- **9 сцен** на одном аудиодвижке — см. таблицу ниже. Три сцены 1.0 перенесены на новый движок без потери поведения.
- **Scene Browser** (`B`): сетка с миниатюрами, которые движок рендерит при первом открытии, и фильтрами GEOMETRY / PARTICLES / WAVEFORMS / ABSTRACT / EXPERIMENTAL.
- **Inspector** (`S`), вкладки:
  - **SCENE** — только параметры текущей сцены, по группам: GEOMETRY, ANIMATION, AUDIO, CAMERA, COLORS. Сброс параметра и всей сцены.
  - **FX** — стек пост-эффектов.
  - **PRESETS** — пресеты.
  - **SYSTEM** — профиль производительности, reduced motion, FFT 2048 / 4096.
- **Аудиомодуляция** (кнопка `~` у параметра): источник OFF / BASS / MIDS / TREBLE / FULL / KICK / SNARE / RMS / LFO; AMOUNT, ATTACK, RELEASE, THRESHOLD, MIN / MAX (окно входа), CURVE (LINEAR / EXP / LOG / S-CURVE), INVERT. На слайдере видно живое значение и огибающую. Огибающая attack/release не зависит от частоты кадров, поэтому скачков нет. Модулировать можно и параметры эффектов.
- **Пост-эффекты**: BLOOM, MOTION TRAILS, KALEIDOSCOPE, CHROMATIC ABERRATION, PIXELATE, GLITCH, FILM GRAIN, VIGNETTE. Добавить / настроить / включить-выключить / переставить / удалить; стек сохраняется в пресете и попадает в экспорт. Профиль производительности ограничивает число активных эффектов. Состояние анимации у каждого эффекта своё (два KALEIDOSCOPE вращаются независимо) и освобождается, когда эффект удалён или выключен. **MOTION TRAILS рендерится не больше двух**: каждый хранит собственную полноразмерную историю кадров (≈ 133 МБ видеопамяти в 4K). Третий и следующие остаются в стеке, но обходятся — вкладка FX помечает их «BYPASSED».
- **Пресеты**: 17 встроенных (минимум один на сцену). Свои: сохранить, перезаписать, переименовать, дублировать, удалить, экспорт / импорт JSON, ссылка `#preset=…`. Пресет содержит сцену, параметры, цвета, камеру, модуляции, стек эффектов и версию схемы; старые данные 1.0 мигрируются, пресеты из более новой версии отклоняются. Ссылка — только diff от значений по умолчанию, ≤ 6000 символов, **никогда не содержит аудио**; всё импортируемое валидируется и ограничивается по размеру.
  - **Библиотека — до 200 своих пресетов.** Когда она заполнена, новый пресет не сохраняется (с сообщением), а старые никогда не вытесняются.
  - **EXPORT ALL / IMPORT JSON.** Импорт принимает до 200 пресетов и до 8 МБ: резервная копия полной библиотеки максимально сложных пресетов (≈ 3.8 МБ) восстанавливается целиком. Размер файла проверяется до чтения. Уже имеющиеся пресеты при повторном восстановлении не дублируются; то, что не поместилось, перечисляется в сообщении. Если копия всё же превысит лимит, EXPORT ALL разбивает её на несколько файлов.
- **HIDE UI** (`H` или кнопка в шапке): остаётся только визуализатор — без шапки, плеера, панелей, переключателей, подписей. Звук и WebGL-контекст при этом не прерываются, режим не зависит от fullscreen. Вернуть интерфейс: `H`, `Esc`, кнопка **SHOW UI** в правом верхнем углу (появляется при наведении, на тач-экране — по касанию).
- **Кадр экспорта в превью**: FULL / 16:9 / 9:16 / 1:1 + **SAFE** (безопасные зоны Shorts / Reels / TikTok). Камера перекомпонуется под формат (отъезжает, чтобы объект поместился), а не обрезается по центру.
- **Export Studio** (`E`) — см. раздел «Экспорт видео».
- **Клавиши** (когда фокус не в поле ввода): `Space` play/pause, `← →` ±5 с, `[ ]` предыдущая / следующая сцена, `1`–`9` сцена по номеру, `B` сцены, `E` экспорт, `H` HIDE UI, `S` инспектор, `F` fullscreen, `L` repeat, `M` mute, `Esc` — выйти из HIDE UI / закрыть верхнюю панель.

### Сцены

| # | Сцена | Категория | Реакция на звук |
| --- | --- | --- | --- |
| 01 | PULSE OBJECT | geometry | бас → масштаб и крупные лопасти; kick → импульс на пружине + контур; mid → складки поверхности; high → рябь и оболочка частиц; snare → бегущее кольцо |
| 02 | RADIAL SPECTRUM | waveforms | 192 лог-полосы; низы — длинные и медленные, верха — короткие и быстрые; история → уходящий туннель; hat → частицы из своей полосы |
| 03 | WAVE FIELD | waveforms | строки — снимки музыки, уезжающие вглубь; бас → широкие волны; mid → изгиб; high → мелкая рябь |
| 04 | REACTIVE MESH | geometry | каркасный рельеф-«водопад» спектра (плоскость / спираль / чаша); бас → бегущие волны; kick → расходящееся кольцо; treble → мелкая фактура |
| 05 | COSMIC RINGS | waveforms | светящиеся полярные кольца, у каждого своя полоса; kick → волна от центра наружу; mids → лепестки; симметрия → калейдоскопические сегменты |
| 06 | PARTICLE CLOUD | particles | GPU-частицы с морфингом облако → спиральная галактика → сфера; у каждой частицы своя полоса; kick → «вдох»; mids → турбулентность |
| 07 | INFINITE AUDIO TUNNEL | geometry | бесконечный туннель колец и спиц; бас + kick → тяга полёта (пружина); импульсы уходят вглубь; изгиб оси |
| 08 | PLASMA FLOW | abstract | жидкий свет (domain warping) со световыми следами; бас → искажение и яркость; mids → детали и цвет; treble → следы |
| 09 | FRACTAL BLOOM | experimental | калейдоскопические кольца и лепестки; низы → внешние слои, верха → внутренние детали; слои вращаются навстречу |

Во всех сценах нет стробоскопа: удары работают через пружины и ограниченные вспышки, в тишине сцена спокойно «дышит».

```
    exporter.ts            старый real-time WebM-рекордер (фолбэк без WebCodecs)

  ui/                    Header, Hero, Hud, PlayerBar, SceneBrowser, ExportStudio, RangeSelector,

```

**Конвейер кадра** — общий для живой сцены и экспорта:

1. `AudioFrame` из анализатора.
2. `AudioFeatureProvider` применяет аудионастройки сцены.
3. `ModulationEngine` вычисляет модулированные параметры.
4. `scene.update(ctx)` обновляет uniforms и камеру.
5. `PostProcessingPipeline` — эффекты и цветокоррекция.
6. Кадр выводится на canvas.

Движок не читает системные часы: время, `dt` и случайность (с сидом) приходят извне. Поэтому одинаковый вход всегда даёт одинаковые кадры.

**Добавить сцену:**

1. Описание в `scenes/defs/`.
2. Реализация в `scenes/<имя>.ts` с экспортом `create`.
3. Строка в `factories.ts` и `registry.ts`.

Браузер сцен, инспектор, пресеты, миниатюры и экспорт подхватят её сами. Реестр проверяет схему параметров при регистрации: диапазоны, значения по умолчанию, варианты.

### Аудиодвижок и анализ

Основа как в 1.0:
- один `MediaElementAudioSourceNode` на сеанс;
- анализатор стоит до громкости;
- компенсация задержки вывода (`AV SYNC +N MS` в HUD), до 0.4 с; буфер задержки рассчитан на частоту анализа до 250 Гц, поэтому работает и на экранах 144 / 240 Гц;
- онсеты: spectral flux + адаптивные пороги;
- предварительный анализ в Web Worker даёт карту событий и BPM; событие точно на 0 с срабатывает один раз при старте, повторе (loop) и перемотке в начало, а события пропущенного при перемотке участка — нет;
- Play во время запуска `AudioContext` отменяется паузой, загрузкой другого файла или закрытием страницы — звук не начинает играть «сам».

**Аудионастройки сцены под модуляцией.** BASS, MIDS, TREBLE, SUB BASS, KICK / SNARE IMPACT, TRANSIENT SENSITIVITY и NOISE GATE можно модулировать — и сцена получает признаки с уже модулированными значениями. Источники модуляции считаются по базовым настройкам, так что параметр не усиливает сам себя; огибающая каждой привязки обновляется один раз за кадр (одинаково в живом режиме и в экспорте).

Классификация kick / snare / hat — **эвристика** по форме транзиента на готовом миксе, а не разделение инструментов.

## Экспорт видео

**Export Studio** (`E`) рендерит видео **офлайн, кадр за кадром** на отдельном canvas точного размера — независимо от окна, частоты кадров экрана и интерфейса (UI в видео не попадает никогда).

**Настройки:**
- контейнер и кодек;
- формат кадра и разрешение;
- FPS;
- качество;
- детализация рендера (BALANCED / QUALITY / ULTRA — не зависит от живого профиля);
- диапазон: весь трек или фрагмент на waveform с двумя маркерами и кнопками 15 / 30 / 60 с;
- вывод: в память со скачиванием или WRITE TO DISK.

Диапазон относится к загруженному треку: при загрузке другого файла выделение сбрасывается на его начало (первые 30 с или весь трек, если он короче), а при запуске экспорта ещё раз ограничивается длительностью трека. Трек короче 0.5 с экспортируется целиком.

Перед стартом показаны длительность, разрешение, FPS, кодеки, оценка размера и ресурсов. Кнопка **RENDER PREVIEW FRAME** показывает настоящий кадр экспорта.

**Как это работает:**
- **Время кадров.** Кадр n показывает музыкальное время `t = start + n / fps` и получает метку `n / fps`; фрагмент всегда начинается с 0.
- **Аудиоанализ.** Для каждого кадра анализ смотрит на звук в середине интервала показа кадра. Поэтому событие попадает на ближайший к нему кадр, а не на следующий.
- **Пре-ролл.** Перед фрагментом 3 с музыки прогоняются через анализ и сцену, чтобы пружины, затухания и trails были «прогреты». Последняя секунда пре-ролла рисуется, в файл не попадает.
- **Звук.** Источник — сам файл, не микрофон. Декодируется потоково (Mediabunny; если контейнер не читается — Web Audio). Обрезается до сэмпла `[start, end)`, пишется стерео 48 кГц. Задержка (priming) кодировщика AAC убирается списком правок (edit list) контейнера.
- **Анализ звука.** Тот же, что в живом режиме: эмуляция `AnalyserNode` (`PcmAnalyser`) поверх кольцевого буфера на 8 с плюс карта событий из предварительного анализа.
- **Кодирование.**
  - WebCodecs через Mediabunny (`CanvasSource`, `AudioSampleSource`), с ожиданием кодировщика (backpressure).
  - Медленный компьютер рендерит дольше, но **кадры не пропускаются**.
  - MP4 / MOV пишутся с fast start в режиме `reserve`: место под заголовок резервируется в начале, а данные уходят в выход по мере кодирования, а не копятся до конца.
  - `VideoFrame` и аудиосэмплы освобождаются; GPU-контекст экспорта уничтожается в конце — и при успехе, и при отмене, и при ошибке (в том числе до начала рендера).
- **Отмена.** Работает на всех этапах, включая FINALIZING: библиотека доводит финализацию до конца, после чего результат отбрасывается. Неотменяемый только последний шаг **SAVING** (фиксация готового файла на диске) — на нём кнопка CANCEL заменяется пояснением. «Ничего не сохранено» показывается только тогда, когда файл действительно не записан.
- **WRITE TO DISK.**
  - Пишет через File System Access API (Chrome / Edge) во временную копию браузера. Существующий файл заменяется **только** после полностью успешного экспорта.
  - При отмене, ошибке рендера, кодировщика или финализации, а также если модуль рендера не загрузился, запись прерывается (`abort`) — прежнее содержимое файла остаётся целым.
  - Почему так: Mediabunny закрывает свой поток и при отмене, а закрытие `FileSystemWritableFileStream` фиксирует данные. Поэтому библиотека получает промежуточный поток, а настоящий файл закрывается только при успехе.
- **Память (IN MEMORY → DOWNLOAD).**
  - Перед стартом — предварительная **оценка** размера по битрейту; если она больше 1.5 ГБ, студия предлагает WRITE TO DISK.
  - Настоящая защита — счётчик **фактически записанных** байтов: экспорт останавливается, как только файл перерастает 1.5 ГБ, с предложением WRITE TO DISK или более короткого фрагмента. Счётчик отстаёт от кодировщика не больше чем на ~512 КБ (данные передаются блоками по 256 КБ).
  - Результат собирается из частей `Blob` без лишней копии в конце.

### Форматы

| Контейнер | Видео | Звук |
| --- | --- | --- |
| MP4 | H.264 / AVC, H.265 / HEVC | AAC-LC 48 кГц стерео (192 / 256 кбит/с) |
| MOV (QuickTime) | H.264 / AVC, H.265 / HEVC | AAC-LC 48 кГц стерео |
| WebM | VP9, VP8 | Opus 48 кГц стерео |

- **Размеры:**
  - 16:9 — 1280×720, 1920×1080, 3840×2160;
  - 9:16 — 720×1280, 1080×1920, 2160×3840;
  - 1:1 — 1080×1080.
- **FPS:** 24 / 25 / **30** (по умолчанию) / 60.
- **Качество:** LOW / STANDARD / HIGH / VERY HIGH. Это целевой битрейт (бит на пиксель с учётом кодека и FPS), а не CRF: WebCodecs принимает битрейт.

**Доступность определяется на устройстве, а не предполагается:**
- Каждая комбинация проверяется в Mediabunny (`canEncodeVideo` / `canEncodeAudio`) с реальными размером, FPS и битрейтом.
- Для HEVC и для кадров больше 1920×1088 дополнительно кодируется пробный ролик из 3 кадров.
- Неподдерживаемые варианты недоступны, и указана причина.
- **H.265 предлагается только при реальном кодировщике** — фиктивной поддержки и подмены нет.
- **WebM никогда не переименовывается в MP4 / MOV.** Расширение и MIME всегда соответствуют контейнеру; MOV — настоящий QuickTime (`major_brand=qt`).

**AAC.** Используется системный кодировщик браузера, если он поддерживает хотя бы один из предлагаемых битрейтов. Только если системного AAC нет совсем (например, сборки браузера без AAC), подгружается WASM-кодировщик `@mediabunny/aac-encoder` (~1 МБ, отдельный чанк, только по требованию). Его задержка в 1024 сэмпла компенсируется так же, через edit list.

**Без сервера и FFmpeg.** Сервер не нужен, FFmpeg WebAssembly не используется. Mediabunny (≈ 175 КБ gzip) и WASM AAC загружаются только при экспорте.

**Фолбэк.** Если WebCodecs нет, вместо студии остаётся старый экспорт 1.0: запись WebM в реальном времени через `MediaRecorder`.

### Синхронизация и детерминизм

- **Звук** в готовом файле совпадает с исходником **до сэмпла** (проверено кросс-корреляцией, см. ниже).
- **Видео.** Событие показывается на кадре, ближайшем к моменту звука:
  - на 24 / 30 fps ошибка не больше половины кадра;
  - на 60 fps — до одного кадра (16.7 мс), когда удар приходится ровно на границу кадров и детектору нужен хотя бы кусочек звука.
- **Детерминизм.** Повторный экспорт с теми же настройками даёт **идентичные кадры**. Хеши декодированных кадров (`framemd5`) совпадают; хеш файла может отличаться только метаданными контейнера (время создания).

- `analysisHub`, `eventScheduler` (дополнены) — 60 / 144 / 240 fps при максимальной компенсации задержки; событие на 0 с при старте, паузе, повторе и перемотке; экспорт с нулевой и ненулевой границей.

## Ограничения

- **Браузеры.** Проверено только в Chromium на Windows с Intel UHD. Safari / iOS, Firefox и реальные телефоны не проверялись; мобильная раскладка проверена эмуляцией на 360 и 375 px.
- **Export Studio требует WebCodecs.** Без него остаётся real-time WebM-рекордер 1.0: идёт в реальном времени, вкладка должна быть видимой, на слабой графике возможны пропуски кадров.
- **HEVC, 4K, 60 fps** зависят от кодировщиков устройства и предлагаются только после успешной проверки. На этой машине нет H.265 4K.
- **WRITE TO DISK** работает только в браузерах с File System Access API (Chrome / Edge). Сохранность файла при отмене, ошибке и финализации проверена с настоящим `FileSystemWritableFileStream` из приватной файловой системы браузера (OPFS); диалог выбора файла автоматически не проверялся (нужно действие пользователя), его ветки покрыты тестами с заглушкой.
- **Последний шаг сохранения на диск (SAVING) отменить нельзя** — это короткая фиксация уже готового файла; интерфейс на этом шаге не предлагает CANCEL.
- **Память.** В режиме «в память» файл до 1.5 ГБ (счётчик отстаёт от кодировщика не больше чем на ~512 КБ). Пиковое потребление — около размера файла плюс буферы кодировщика; большие видео надёжнее писать на диск. Если Mediabunny не может прочитать контейнер, трек декодируется Web Audio целиком (лимит ~900 МБ PCM).
- **MOTION TRAILS** — не больше двух одновременно (см. «Пост-эффекты»); лишние экземпляры сохраняются, но не рендерятся.
- **Отложенный запуск звука** (Play → Pause, пока `AudioContext` ещё не запустился) проверен тестами с заглушкой `AudioContext`: в настоящем браузере `resume()` завершается слишком быстро, чтобы воспроизвести гонку вручную.
- **Треки длиннее 15 минут** не получают предварительный анализ (как в 1.0). Тогда и в экспорте работает только real-time детектор, а ему нужны первые секунды для калибровки порогов: в начале трека отдельные удары могут не сработать.
- **Классификация ударов — эвристика** (см. выше).
- **Миниатюры сцен** рендерятся в браузере при первом открытии Scene Browser — это занимает долю секунды.
- **Скорость экспорта** зависит от GPU; в фоновой вкладке браузер может замедлить рендер (кадры при этом не теряются).

## Отладка

- `?renderer=2d` — принудительно включить Canvas 2D-фолбэк.
- В dev-сборке доступен `window.__beatform`: контроллер, хаб анализа, сторы (`visual`, `ui`, `settings`, `player`), `studio.startExport`, `capabilities`, `plan`, `liveEngine()` и `checks.runExportChecks()` — проверки экспорта с настоящими кодировщиками и файлом в OPFS (`src/dev/exportChecks.ts`; сначала загрузите TEST PATTERN). В production ничего из этого нет.
- В dev-сборке `POST /__dev/save-export?name=<файл>` сохраняет тело запроса в `.exports/` (папка в `.gitignore`), чтобы проверить готовое видео ffprobe. В production-сборке этого эндпоинта нет.
- Проект лежит в папке OneDrive: если HMR пропустил изменение файла, пересохраните файл или перезапустите `npm run dev`.

## Приватность

Аудио не покидает вкладку: нет загрузок на сервер, нет аналитики, нет микрофона. В `localStorage` хранятся только настройки, сцены / пресеты и громкость. Ссылки на пресеты содержат только параметры, никогда не аудио.

## Публикация в Cloudflare Pages

Подключите GitHub-репозиторий через **Workers & Pages → Create application → Pages → Connect to Git**.

| Настройка | Значение |
| --- | --- |
| Production branch | `main` |
| Framework preset | React (Vite), либо None с настройками ниже |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | оставить пустым (корень репозитория) |
| Node.js | `24.19.0`, читается из `.node-version` |

Cloudflare устанавливает зависимости по `package.json` и `package-lock.json`. Переменные окружения, серверная часть и особые заголовки (COOP / COEP) не нужны: экспорт работает на обычном статическом хостинге.

Папки `node_modules/`, `dist/`, `.exports/`, `.claude/` и файлы `.env*` (кроме безопасного `.env.example`) не отправляются в GitHub. После подключения каждый push в `main` запускает новую публикацию.
